## 2. Связь с лекционным материалом

Операционная система является посредником между пользователем, приложениями и аппаратным обеспечением компьютера. Командная оболочка предоставляет интерфейс для взаимодействия с системой с помощью текстовых команд.

В ходе практической работы изучены базовые команды Linux, управление пользователями и группами, права доступа к файлам и каталогам, а также настройка окружения командной оболочки.

## 3. Рабочее окружение и диагностика системы

Работа выполнялась в Ubuntu, запущенной в VirtualBox.

Основной пользователь: `aizyu`.

Дополнительный пользователь: `student2`.

Для получения информации о системе используются следующие команды:

```bash
whoami
pwd
uname -a
lsb_release -a
```

Назначение команд:

- `whoami` — показывает имя текущего пользователя;
- `pwd` — выводит путь к текущему каталогу;
- `uname -a` — показывает сведения о ядре и системе;
- `lsb_release -a` — выводит информацию о дистрибутиве Ubuntu.

Эти команды позволяют проверить, под каким пользователем выполняются действия, в каком каталоге находится терминал и какая операционная система используется.

## 4. Создание пользователя и группы

По условию работы необходимо создать группу `developers`, дополнительного пользователя `student2` и включить пользователя в эту группу.

Для проверки существования пользователя и его групп выполнена команда:

```bash
id student2
```

Результат:

```text
uid=1002(student2) gid=1002(student2) groups=1002(student2),100(users),1001(developers)
```

Вывод показывает, что пользователь `student2` существует и входит в группу `developers`.

**Зачем это нужно?**

Пользователи и группы позволяют разграничивать доступ к ресурсам системы. Вместо настройки прав для каждого пользователя отдельно можно предоставить доступ участникам определённой группы.

## 5. Создание общей папки и настройка прав доступа

По условию необходимо создать каталог `/srv/shared`, назначить владельцем `root`, назначить группу `developers` и настроить права так, чтобы участники группы могли создавать файлы, а остальные пользователи не могли изменять содержимое каталога.

Для проверки выполнена команда:

```bash
ls -ld /srv/shared
```

Результат:

```text
drwxrwsr-x 2 root developers 4096 Oct 1 01:30 /srv/shared
```

В результате проверки установлено:

- владелец каталога — `root`;
- группа каталога — `developers`;
- права доступа — `drwxrwsr-x`.

### Объяснение прав доступа

Запись `drwxrwsr-x` состоит из нескольких частей:

- `d` означает, что объект является каталогом;
- `rwx` — владелец может просматривать каталог, создавать и удалять записи в нём;
- `rws` — участники группы могут просматривать каталог, создавать и удалять записи; буква `s` указывает на установленный бит `setgid`;
- `r-x` — остальные пользователи могут просматривать каталог и обращаться к известным им файлам, но не могут создавать или удалять записи в каталоге.

Бит `setgid` обеспечивает наследование групповой принадлежности `developers` новыми файлами и подкаталогами внутри `/srv/shared`.

Таким образом, права позволяют участникам группы совместно работать с файлами, а остальные пользователи не получают права на изменение содержимого каталога.

## 6. Проверка прав доступа при удалении файла

Чтобы проверить настройки доступа, от имени пользователя `student2` был создан тестовый файл:

```bash
sudo -u student2 touch /srv/shared/test_delete.txt
```

Команда `sudo -u student2` запускает команду от имени пользователя `student2`, а `touch` создаёт пустой файл, если его ещё нет.

Для проверки владельца и группы файла выполнена команда:

```bash
ls -l /srv/shared/test_delete.txt
```

Результат:

```text
-rw-rw-r-- 1 student2 developers 0 Oct 14 22:35 /srv/shared/test_delete.txt
```

Файл принадлежит пользователю `student2` и группе `developers`.

Затем основной пользователь `aizyu` попытался удалить файл без административных прав:

```bash
rm -f /srv/shared/test_delete.txt
```

Результат:

```text
rm: cannot remove '/srv/shared/test_delete.txt': Permission denied
```

Удаление не удалось, потому что основной пользователь не имеет права записи в каталог `/srv/shared`. Для удаления файла Linux проверяет права на родительский каталог, а не только права самого файла.

**Вывод проверки:** настроенные права доступа ограничивают удаление файлов пользователями, которые не имеют права записи в каталоге. Это помогает защитить общие данные от случайного удаления.

## 7. Разница между `su` и `sudo`

Команды `su` и `sudo` позволяют выполнять действия от имени другого пользователя, но работают по-разному.

### Команда `su`

`su` позволяет переключиться на другого пользователя. Например:

```bash
su - student2
```

Команда открывает сеанс пользователя `student2` и обычно требует его пароль. Параметр `-` запускает оболочку с окружением целевого пользователя.

### Команда `sudo`

`sudo` позволяет выполнить отдельную команду с правами другого пользователя, чаще всего администратора `root`, если текущему пользователю это разрешено.

Для проверки выполнена команда:

```bash
sudo whoami
```

Результат:

```text
root
```

Это показывает, что команда была выполнена с правами `root`.

Для переключения на пользователя `student2` использовались команды:

```bash
sudo su - student2
whoami
```

Результат:

```text
student2
```

### Почему в Ubuntu по умолчанию заблокирован прямой вход под `root`?

В Ubuntu учётная запись `root` обычно не имеет установленного пароля для прямого входа. Вместо постоянной работы с максимальными привилегиями система предлагает использовать `sudo` для отдельных административных команд.

Это повышает безопасность: пользователь получает административные права только тогда, когда они действительно нужны, а риск случайно изменить или удалить важные системные файлы уменьшается.

## 8. Настройка `.bashrc`

Файл `~/.bashrc` содержит настройки командной оболочки Bash. В него можно добавлять alias и переменные окружения, чтобы использовать их в новых сеансах терминала.

В файл `~/.bashrc` были добавлены следующие строки:

```bash
alias ll='ls -la'
alias c='clear'
export COURSE="OS"
```

### Назначение настроек

- `alias ll='ls -la'` — создаёт короткую команду `ll`, которая выводит подробный список файлов, включая скрытые;
- `alias c='clear'` — создаёт команду `c` для очистки экрана терминала;
- `export COURSE="OS"` — создаёт переменную окружения `COURSE` со значением `OS` и делает её доступной дочерним процессам.

### Проверка переменной окружения

Выполнена команда:

```bash
echo $COURSE
```

Результат:

```text
OS
```

Это подтверждает, что переменная окружения доступна в текущем сеансе.

### Проверка alias

Для проверки первого alias выполнена команда:

```bash
alias ll
```

Результат:

```text
alias ll='ls -la'
```

Для проверки второго alias выполнена команда:

```bash
alias c
```

Результат:

```text
alias c='clear'
```

Оба alias определены и доступны в оболочке Bash.

Настройки также были проверены в новой вкладке терминала. Переменная `COURSE` и оба alias сохранили свои значения, что подтверждает загрузку настроек `.bashrc` в новом сеансе.

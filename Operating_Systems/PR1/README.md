# Практическая работа №1. Диагностическое тестирование и знакомство с Linux

## 1. Цель работы

Познакомиться с Linux и основными командами терминала, настроить пользователей и группы, проверить права доступа к общей папке и настроить переменные окружения.

## 2. Среда выполнения

- Операционная система: Ubuntu в VirtualBox.
- Основной пользователь: `aizyu`.
- Дополнительный пользователь: `student2`.
- Вариант: B.

## 3. Создание пользователя и группы

Для проверки пользователя была выполнена команда:

```bash
id student2
```

Результат:

```text
uid=1002(student2) gid=1002(student2) groups=1002(student2),100(users),1001(developers)
```

Пользователь `student2` существует и входит в группу `developers`.

## 4. Создание общей папки и настройка прав доступа

Для проверки каталога была выполнена команда:

```bash
ls -ld /srv/shared
```

Результат:

```text
drwxrwsr-x 2 root developers 4096 Oct 1 01:30 /srv/shared
```

Владелец каталога — `root`, группа — `developers`.

Права `drwxrwsr-x` означают, что владелец и участники группы могут записывать данные в каталог. Остальные пользователи могут просматривать содержимое, но не могут создавать или удалять файлы в этом каталоге.

Бит setgid (`s`) обеспечивает наследование групповой принадлежности `developers` новыми файлами и каталогами внутри `/srv/shared`.

## 5. Проверка прав доступа

От имени `student2` был создан тестовый файл:

```bash
sudo -u student2 touch /srv/shared/test_delete.txt
```

Проверка файла:

```bash
ls -l /srv/shared/test_delete.txt
```

Результат:

```text
-rw-rw-r-- 1 student2 developers 0 Oct 14 22:35 /srv/shared/test_delete.txt
```

Основной пользователь `aizyu` попытался удалить файл:

```bash
rm -f /srv/shared/test_delete.txt
```

Результат:

```text
rm: cannot remove '/srv/shared/test_delete.txt': Permission denied
```

Удаление не удалось, потому что у основного пользователя нет права записи в каталог `/srv/shared`. Таким образом, проверка подтвердила работу настроенных прав доступа.

## 6. Разница между su и sudo

Команда `su` позволяет переключиться на другого пользователя. При обычном использовании `su - student2` потребуется пароль пользователя `student2`.

Команда `sudo` позволяет выполнять команды с административными правами, если у пользователя есть соответствующие разрешения.

Проверка:

```bash
sudo whoami
```

Результат:

```text
root
```

Для переключения на пользователя `student2` с административными правами использовались команды:

```bash
sudo su - student2
whoami
```

Результат:

```text
student2
```

В Ubuntu прямой вход под `root` обычно отключён по умолчанию. Использование `sudo` позволяет выполнять административные команды по необходимости и не работать постоянно с правами суперпользователя.

## 7. Настройка .bashrc

В файл `~/.bashrc` добавлены настройки:

```bash
alias ll='ls -la'
alias c='clear'
export COURSE="OS"
```

Проверка переменной окружения:

```bash
echo $COURSE
```

Результат:

```text
OS
```

Проверка первого alias:

```bash
alias ll
```

Результат:

```text
alias ll='ls -la'
```

Проверка второго alias:

```bash
alias c
```

Результат:

```text
alias c='clear'
```

Настройки были проверены в новой вкладке терминала. Переменная `COURSE` и оба alias сохранили свои значения.

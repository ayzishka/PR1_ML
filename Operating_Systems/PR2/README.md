## 2. Исходные данные и структура проекта

- `report.sh` — Bash-скрипт для подсчёта сообщений по модулям;

## 3. Анализ журналов с помощью Bash

### 3.1. Реализация `report.sh`

Скрипт принимает путь к каталогу с журналами, уровень сообщений `ERROR` или `WARN` и необязательный параметр `--top N`.

Основные возможности:

1. Проверка наличия обязательных аргументов.
2. Проверка существования указанного каталога.
3. Проверка допустимого уровня сообщений.
4. Подсчёт сообщений для каждого модуля.
5. Сортировка модулей по убыванию количества сообщений.
6. Вывод только заданного количества модулей с помощью `--top N`.
7. Завершение с кодом `1` при ошибках аргументов или отсутствии каталога.

### 3.4. Проверка корректности скрипта

При запуске без обязательных аргументов скрипт выводит справку:

```text
Usage: ./report.sh <directory> <ERROR|WARN> [--top N]
```

Код завершения — `1`.

При указании несуществующего каталога:

```text

```

Код завершения также равен `1`.

Дополнительно выполнена проверка:

```bash

```

Команда завершилась с кодом `0` и не вывела сообщений об ошибках.

Таким образом, скрипт корректно обрабатывает проверенные входные данные и ошибки аргументов.

## 4. Определение размера файла с помощью Python

Скрипт `hello.py` принимает путь к файлу, открывает его в бинарном режиме, считывает содержимое и выводит размер в байтах. При ошибке чтения программа выводит сообщение в поток ошибок и завершает работу с кодом `1`.

Команда:

## 5. Анализ системных вызовов

### 5.1. Трассировка Python

Для записи системных вызовов Python использована команда:

```bash
strace -f -o trace.txt python3 hello.py data/01.log
```

Параметр `-f` позволяет отслеживать вызовы процесса и его дочерних процессов, а `-o` сохраняет трассировку в файл.

Для получения сводной статистики выполнена команда:

```bash
strace -c python3 hello.py data/01.log > /dev/null
```

По результатам выполнения зарегистрировано **397 системных вызовов**, из которых 44 завершились ошибкой.

В сводке присутствуют, например, следующие вызовы:

| Системный вызов | Количество |
|---|---:|
| `newfstatat` | 69 |
| `mmap` | 23 |
| `openat` | 30 |
| `read` | 28 |
| `close` | 25 |
| `mprotect` | 10 |

Эти значения относятся ко всему процессу Python, включая запуск интерпретатора, загрузку библиотек и выполнение служебных операций.

Число 44 обозначает количество системных вызовов, завершившихся ошибкой, а не количество ошибок Python-программы. Некоторые такие обращения могут быть ожидаемой частью работы интерпретатора.

### 5.2. Подробный анализ чтения файла

Для более подробной трассировки использована команда:

```bash
strace -f -yy -o trace_detailed.txt python3 hello.py data/01.log
```

Параметр `-yy` помогает определить, с какими файлами связаны файловые дескрипторы.

В `trace_detailed.txt` обнаружено девять системных вызовов, непосредственно связанных с обработкой `data/01.log`:

- `openat()` — открывает файл;
- `fstat()` — получает информацию о файле;
- `ioctl()` — выполняет запрос к файловому дескриптору;
- `lseek()` — получает или изменяет позицию чтения;
- `read()` — читает содержимое файла;
- `close()` — закрывает файл.

В частности, трассировка содержит следующие результаты:

```text
read(..., 19077) = 19076
read(..., "", 1) = 0
```

Первый вызов успешно прочитал 19 076 байт. Второй вернул `0`, что означает достижение конца файла.

Всего в сводке Python зарегистрировано 28 вызовов `read()`, поскольку интерпретатор также читает данные, необходимые для запуска и работы программы. Поэтому общее количество вызовов `read()` не совпадает с количеством операций чтения целевого журнала.

### 5.3. Почему Python выполняет дополнительные системные вызовы

Python — интерпретируемый язык. До выполнения пользовательского кода интерпретатор должен запуститься, загрузить необходимые библиотеки и подготовить память.

Например:

- `mmap()` используется для отображения областей памяти;
- `mprotect()` изменяет права доступа к областям памяти;
- `openat()` открывает файлы;
- `read()` считывает данные;
- `close()` закрывает файловые дескрипторы.

Поэтому значительная часть системных вызовов связана не только с чтением `data/01.log`, но и с подготовкой и выполнением интерпретатора.

## 6. Сравнение `cat` и Python

Для сравнения использован один и тот же файл `data/01.log`.

Трассировка команды `cat`:

```bash
strace -f -o trace_cat.txt cat data/01.log
```

Подсчёт системных вызовов:

```bash
strace -c cat data/01.log > /dev/null
```

Для Python:

```bash
strace -c python3 hello.py data/01.log > /dev/null
```

Результаты эксперимента:

| Показатель | `cat` | `python3 hello.py` |
|---|---:|---:|
| Всего системных вызовов | 46 | 397 |
| Вызовы с ошибками | 1 | 44 |
| `read()` | 3 | 28 |
| `openat()` | 4 | 30 |
| `close()` | 6 | 25 |

Python выполнил на **351 системный вызов больше**, чем `cat`.

Отношение количества системных вызовов:

\[
\frac{397}{46} \approx 8{,}63
\]

В данном эксперименте Python выполнил примерно в 8,63 раза больше системных вызовов.

Это объясняется тем, что `cat` — простая утилита для вывода содержимого файла, а Python дополнительно выполняет операции, связанные с запуском интерпретатора и загрузкой библиотек.

Количество системных вызовов помогает оценить объём системной работы, но само по себе не определяет полную производительность программы.

## 7. Ответы на контрольные вопросы

### 1. Почему нельзя обратиться к диску напрямую из пользовательской программы?

Пользовательские программы работают с ограниченными правами и не могут произвольно управлять аппаратными устройствами. Это необходимо для безопасности и стабильности системы.

Для работы с файлами программа обращается к ядру операционной системы через системные вызовы. Ядро проверяет права доступа и выполняет необходимые операции.

### 2. Что дороже — вызов функции или системный вызов, и почему?

Обычно системный вызов требует больше накладных расходов, чем обычный вызов функции. При системном вызове управление передаётся ядру операционной системы, после чего возвращается программе.

Обычная функция, как правило, выполняется внутри пользовательского процесса без такого перехода. Однако фактическая стоимость зависит от конкретной операции и условий выполнения.

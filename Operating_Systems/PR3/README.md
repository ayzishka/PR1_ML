## Цель работы

Изучить процессы Linux, работу системных вызовов `fork()`, `exec()` и `waitpid()`, а также состояния zombie и orphan. Исследовать дерево процессов и механизм Copy-on-Write.

## 1. Дерево процессов — `ptree.py`

Программа читает информацию из `/proc`, отбирает процессы текущего пользователя и выводит их в виде дерева.

Для каждого процесса отображаются:
- PID — идентификатор процесса;
- STATE — состояние процесса;
- RSS — объём резидентной памяти в kB.

**Запуск:**

```bash
python3 Operating_Systems/PR3/ptree.py
```

**Результат:** программа успешно вывела дерево процессов. В выводе присутствовали PID, состояния `S` и `R`, а также значения RSS в kB.

## 2. Создание процессов — `runner.py`

Программа создаёт дочерние процессы через `fork()`, запускает команду через `exec()` и ожидает завершения всех детей.

**Запуск:**

```bash
python3 Operating_Systems/PR3/runner.py 3 /bin/true
```

**Полученный результат:**

```text
PID=5685 | код возврата=0 | время=0.002 с
PID=5686 | код возврата=0 | время=0.002 с
PID=5687 | код возврата=0 | время=0.002 с
```

Все три процесса завершились успешно с кодом возврата `0`.

## 3. Zombie-процесс — `zombie_demo.py`

Zombie — это завершившийся дочерний процесс, статус которого родитель ещё не забрал с помощью `wait()` или `waitpid()`.

**Запуск:**

```bash
python3 Operating_Systems/PR3/zombie_demo.py
```

**Полученный результат:**

```text
Родительский процесс PID=5717
Дочерний процесс PID=5718
Дочерний процесс PID=5718 завершился.
Состояние дочернего процесса: State: Z (zombie)
Через 10 секунд родитель вызовет waitpid().
Дочерний процесс собран через waitpid(); zombie устранён.
```

В ходе демонстрации дочерний процесс находился в состоянии `Z`. После вызова `waitpid()` родитель забрал его статус, и zombie был устранён.

## 4. Orphan-процесс — `orphan_demo.py`

Orphan — это процесс, родитель которого завершился раньше него. Такой процесс продолжает работу, а его родителем становится процесс, выполняющий функцию усыновления.

**Запуск:**

```bash
python3 Operating_Systems/PR3/orphan_demo.py
```

**Полученный результат:**

```text
Родительский процесс: PID=5778
Дочерний процесс: PID=5779
Родитель завершится раньше дочернего.
Дочерний процесс: PID=5779, новый PPID=1697
```

Дополнительная проверка:

```bash
ps -p 1697 -o pid,ppid,comm,args
```

Результат:

```text
PID    PPID COMMAND  COMMAND
1697   1    systemd  /usr/lib/systemd/systemd --user
```

В данной системе дочерний процесс был усыновлён пользовательским процессом `systemd --user` с PID `1697`. Его PPID равен `1`.

## 5. Copy-on-Write — `cow_memory.py`

Copy-on-Write (COW) позволяет родителю и дочернему процессу первоначально использовать общие физические страницы памяти после `fork()`. При изменении данных ОС создаёт отдельные копии затронутых страниц.

**Запуск:**

```bash
python3 Operating_Systems/PR3/cow_memory.py
```

**Полученный результат:**

```text
Родитель PID=5814, размер списка=2000000
Ребёнок PID=5815
RSS до изменения: 22396 kB
RSS после изменения: 22524 kB
Родитель дождался завершения ребёнка.
```

RSS увеличился на 128 kB. Это измерение показывает изменение резидентной памяти процесса, но само по себе не позволяет точно определить весь объём физических страниц, скопированных механизмом COW.

## Ответы на контрольные вопросы

### 1. Почему `fork()` возвращает два разных значения?

`fork()` создаёт дочерний процесс. В родительском процессе вызов возвращает PID дочернего процесса, а в дочернем — `0`. Если создание не удалось, родитель получает `-1`.

### 2. Что изменится, если вызвать `exec()` без предварительного `fork()`?

`exec()` заменяет текущую программу новым исполняемым файлом в том же процессе. PID обычно сохраняется, а код и данные прежней программы заменяются. Если предварительно вызвать `fork()`, новая программа запускается в дочернем процессе, а родитель может продолжить работу и дождаться его завершения.
